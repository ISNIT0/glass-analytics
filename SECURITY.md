# Security policy

Dataflare runs inside people's Cloudflare accounts and handles their users' data, so we take security reports seriously.

## Reporting a vulnerability

Please **do not open a public issue**. Report privately through [GitHub's private vulnerability reporting](https://github.com/ISNIT0/glass-analytics/security/advisories/new). Include what you found, how to reproduce it, and the impact you expect.

We'll acknowledge your report, keep you updated while we investigate, and credit you in the release notes unless you'd rather we didn't.

## Supported versions

Security fixes go into the latest release. Users get them with `npx dataflare-cli@latest upgrade`.

## Scope notes

- The ingest endpoints (`/e`, `/r`, `/f`) are public by design: browsers send to them. Restrict a project to your origins with `allowed_origins` if you need to.
- `/api` and `/mcp` require the admin key or the read-only key. Keys are generated by `dataflare init`, stored as Worker secrets, and kept locally in `.glass/credentials.json`, which is git-ignored.
- Raw SQL is limited to single read-only statements (`packages/core/src/sql/guard.ts`). Bypasses of that guard are in scope.
